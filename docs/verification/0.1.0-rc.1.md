# 0.1.0-rc.1 verification

Date: 2026-09-08. Target: Paseo 0.7.2, Windows daemon, web client.

This is a release-candidate verification record, not certification of all host/client combinations. Source checks cover commit `a5a9c392664ef2fbc01b10ccc9e7c164bb044835`; subsequent documentation-only commits do not change the tested plugin source.

## Source checks

`npm run check` passes in [Windows, macOS and Ubuntu CI](https://github.com/SWBaek/Paseo-Plugin/actions/runs/34175316499) with Node 22. It checks documentation synchronization, Git-source runtime imports, release metadata, all workspace types and tests. Windows executes 164 tests. Non-Windows runners omit Windows-specific File Browser filesystem/download tests, as documented in the test runner; they still exercise portable configuration, archive filtering and view tests.

Regression coverage includes invalid/missing configuration, cached configuration lifetime, configured-root ancestor junction replacement, read-only Git/GitHub/Tailscale command boundaries, provider HTTP redirect refusal with a real local redirect server, and basic Tailscale data without an extension backend. No credentials or tokens are included in this record.

## Runtime and UI

On an already-enabled Windows Paseo 0.7.2 daemon, all seven plugins were installed from the public Git branch under separate `*-release-check` IDs. Every installation reached `running` without a `node_modules` directory in its managed plugin directory. Initial installs used `42b8dae85a15e0b80e22dd93149b56bf2a6fb512`; File Browser, GitHub Project Board and Tailscale Dashboard successfully updated to `a5a9c392664ef2fbc01b10ccc9e7c164bb044835`. The other four plugins have identical source between these commits. All seven temporary Git installations were removed after verification; a final listing confirmed the original seven directory installations still running with no errors. The daemon was not restarted.

The real Chrome web client exercised:

- File Browser: configured roots, nested navigation, Markdown preview and root switching that clears the previous preview. An invalid empty-root configuration displayed its setup error and exposed zero root selectors; valid host configuration was restored afterward.
- GitHub Project Board: the default `@me` owner loaded the authenticated user's project list and board.
- Tailscale Dashboard: live connection/peer data and the available extension dashboard rendered together, with exactly one basic connection card. Backend-absent behavior is regression-tested, not claimed as a live environment test.
- Branch Garden: a real workspace scan rendered results and an expected missing-base-ref warning without modifying Git state.
- Provider Usage: actual authenticated Codex and Grok usage states rendered. Private account values are not published as screenshots.
- Composer Compact: confirmation opened and Cancel dismissed it; no `/compact` command was sent.
- Composer Skills: the actual session catalog populated, selection generated a draft, and an insecure-HTTP clipboard failure retained a manually copyable draft. Cancel left the agent composer empty; secure-context clipboard success was not tested in this session.

UI impact **D** applies to File Browser root navigation and Tailscale's new section. Both were visually reviewed at 1440×1000 and 390×844 in light and dark themes. Surface geometry checks found no horizontal overflow; File Browser root targets were at least 44px high and had button roles and root-specific accessible labels. File Browser's configuration error was also checked in wide/dark. [File Browser screenshots](../screenshots/) contain only this public repository's content; Tailscale screenshots remain local because they contain host details.

Other changes are **A** (server/configuration/release documentation), so a repeated four-environment UI matrix is unnecessary for those plugins. The Composer confirmation received an additional representative dark/wide smoke check; [actual modal](../screenshots/composer-compact-dark.png).

Remaining limits: no live macOS/Linux daemon or native iOS/Android client verification; no screen-reader session; no end-to-end Tailnet download or secure clipboard success in this pass. ZIP/download safety has Windows automated coverage. Failed Git-candidate rollback was not re-executed on 0.7.2; the earlier recorded rollback experiment must not be treated as current-version evidence. These limits keep this version a preview release candidate.

## Independent review

A separate Astra agent reviewed the implementation independently. Its initial findings led to redirect refusal, least-privilege scope guidance, fail-closed configuration, rejection of junctions in configured-root ancestors, release-tag collision rejection and removal of a duplicated Tailscale status card. Regression tests cover the source fixes. Final independent Astra review found no remaining blocking findings and judged this preview release candidate ready within the documented scope. The reviewer independently checked the final diff, all five public screenshots, successful three-OS CI at the stated SHA, documentation synchronization and release metadata.
